# trajectory-visual-server 接口说明

基础路径：`/api/visual`；统一响应 `Result<T>`：`{code,message,data}`，`code=200` 成功，`404`=无数据/不可用。

## 一、运单

### GET /waybill/page
查询参数：`current,size,waybillNo,vehicleId,plateNo,startTime,endTime,dataStatus`
（startTime/endTime 格式 `yyyy-MM-dd HH:mm:ss`，与轨迹时间范围重叠即命中）。
返回 `data.total/records[]`，records 即 `trajectory_waybill` 元数据，含从业务库回填的
`plateNo / materialName / sendAddrName|Area|Detail / sendLon|Lat / receiveAddrName|Area|Detail /
receiveLon|Lat / loadTime / unloadTime / orderTime`（即"收发货时间与地点 + 收发坐标"，
供工作台展示与地图标记）。

### GET /waybill/detail/{waybillId}
返回该运单元数据（同上字段）。

### POST /waybill/admin/import-waybills?limit=
扫描 `trajectory.source.full-data-dir`（track_*.json）按 waybill_id 去重导入，并按 waybill_id
从业务库 `waybill` 表回填车牌、货物、收发货地点/坐标（`send_addr_lal`/`receive_addr_lal`，格式
`lon,lat`）与装货/卸货/接单时间。**历史运单需重跑一次本接口才会补齐这些字段。**
返回 `{total,imported,updated,failed,sourceDir}`。

## 二、轨迹

坐标说明：所有返回点坐标为 **GCJ-02**。源 JSON 与业务库地址坐标本身即 GCJ-02（入湖前已做过一次
WGS84→GCJ-02），接口**不再做二次转换**（口径见 `trajectory.coord.source-already-gcj02`，默认 true）；
压缩与指标计算不依赖坐标基准。

### GET /trajectory/original/{waybillId}
原始轨迹 = 清洗后全量点 + 停留单元（startTime/endTime/label REST|TRAFFIC/durationS/起终锚点坐标/retainedBoth）。
返回 TrackViewVO。

**"被删点"只在运单已压缩时才有**：未压缩（Mongo 无分片）时每个点 `kept=null`、`deletedPointCount=null`，
前端不会画任何高亮点；压缩后才逐点给 `kept`（true=保留、false=被有损压缩删除）并给出
`keptPointCount` / `deletedPointCount`，前端据此把被删点高亮出来。
实现上按分片里落库的同一套参数（容差/精度/块长）重跑一次分级抽稀复现，并校验保留点数与分片记录
`keptPointCount` 一致；不一致（参数变更过）则返回 null 并提示重新压缩，不画可能有误的标记。
`metrics` 给原始侧点数口径。

### GET /trajectory/compressed/{waybillId}
压缩后轨迹 = 解码 Mongo 分片的保留点 + 停留元数据；未压缩时 `notice` 提示、无 points。
返回 TrackViewVO，其中 `metrics` = 压缩指标快照（分片落库的 `metrics` 字段回读）：
`rawPointCount,cleanedPointCount,keptPointCount,stopCount,anchorCount,chunkCount,crLossy,crLossless,
crTotal,naiveBytes,storageBytes,pedAvgM,pedMaxM,sedAvgM,sedMaxM,sr,unitIntegrity,dwellFidelity,
encodeMs,decodeMs,moveToleranceM,precision,blockWindowS`。
2026-09-10 之前压的旧分片没有该快照，此时只有点数与存储字节可用、压缩率等返回 null（前端显示"—"），
`metrics.message` 会提示"重新压缩后可显示完整指标"。

### GET /trajectory/config
压缩与坐标口径快照，供前端展示提示、避免硬编码：
`{blockWindowS, precision, moveToleranceM, baselineToleranceM, coordSystem, sourceAlreadyGcj02, sourceDir}`。

### GET /trajectory/algorithm-tracks/{waybillId}
**单运单 × 各算法保留轨迹**（对比页"单运单下钻"的地图数据）：同一运单下本文与 4 条几何基线
（DP/DPS/TD-TR/Trajic）各自最终保留的点，返回
`{waybillId, waybillNo, rawPointCount, cleanedPointCount, baselineToleranceM,
 algorithms:[{algorithmCode, algorithmName, keptPointCount, crLossy, points:[{lon,lat,time,epoch,spd,seq}],
 stops?:[{seq,label,startTime,endTime,durationS,startLon,startLat,endLon,endLat,retainedBoth}]}]}`。
`stops` 只随本文算法返回（几何基线不识别语义），前端据此在地图上标出停留点与停留时长（时:分:秒）。
实现上为**单运单现算**（同一清洗轨迹 + 同一容差重跑各算法，毫秒级）——主实验结果表只存指标、不存基线保留点，
现算比重建一套基线点存储更划算，且与第 6 章实验口径天然一致。

### GET /trajectory/chunks/{waybillId}
Mongo 分片元数据清单：`chunkIndex,startTime,endTime,pointCount,hasAnchor,payloadBytes,chunkCountTotal,blockWindowS,rawPointCount,keptPointCount,stayPointCount`。
`blockWindowS` 是该运单压缩时所用的分块时长（秒），即"多少时长一个分片"，供时间窗页顶部提示。

### POST /trajectory/compress/{waybillId}
对该运单执行压缩并**写 Mongo 分片**（覆盖旧分片），更新元数据状态 COMPRESSED。
返回 `CompressResultVO`：rawPointCount, cleanedPointCount, keptPointCount, stopCount, anchorCount,
chunkCount, crLossy, crLossless, crTotal, naiveBytes, storageBytes, pedAvgM/pedMaxM, sedAvgM/sedMaxM,
sr, unitIntegrity, dwellFidelity, encodeMs, decodeMs, moveToleranceM, precision, blockWindowS, durationMs。

### POST /trajectory/compress-all?limit=
读取源目录做全量压缩（后台任务）。返回 `{taskId,status}`。

### GET /trajectory/compress-task/{taskId}
轮询任务：`status,totalFiles,processed,successCount,failedCount,currentWaybillNo,elapsedMs,failures[]`。

### POST /trajectory/search-by-time
请求体：`{"waybillId":31363,"startTime":"2026-03-22 13:45:00","endTime":"2026-03-22 14:45:00"}`
逻辑：Mongo 时间索引命中与窗口相交的分片 → 只解命中分片 → 与全量解压同窗口点数对比。
返回 WindowSearchVO：`totalChunks,hitChunks,bytesRead,totalBytes,readRatio,blockHitRatio,
partialPoints,fullPoints,consistent,partialMs,fullMs,blockWindowS,trackStartTime,trackEndTime,points[]`；
未压缩返回 `dataStatus=NOT_COMPRESSED`。`blockWindowS/trackStartTime/trackEndTime` 供前端顶部
提示"这片轨迹的时间范围是什么、一片多少秒"。

## 三、评估（数据来自 MySQL 结果表，默认最近含算法结果的成功批次，支持 ?runId=）

### GET /evaluation/runs
实验批次列表（倒序）。

### GET /evaluation/summary?runId=
批次 + KPI + 结论摘要 + dataStatus。

### GET /evaluation/algorithms?runId=
该批次各算法聚合行（PROPOSED/DP/DPS/TD-TR/Trajic）。

### GET /evaluation/algorithm-compare?runId=
算法聚合 + 每条算法明细统计 stats（CR_total/CR_lossy/PED/SED/SR/查询耗时 的 mean/median/min/max）。

### GET /evaluation/waybill/{waybillId}?runId=
单运单 × 各算法明细（下钻表格）。

### GET /evaluation/ablation?runId=
消融变体列表（当前批无则回退到最近含消融数据的批次）。

### GET /evaluation/partial-decompression?runId=
本文方法部分解压性能（kpi + block 时长 series）。

### GET /evaluation/parameter-sensitivity?runId=
`{dpTolerance:[...], blockWindow:[...]}`（当前批无则回退）。

### GET /evaluation/errors?runId=
失败记录。

### GET /evaluation/dashboard?runId=
一次聚合：`run / kpi / algorithmComparison[] / semanticComparison[] / errorComparison[] /
storageQueryComparison{series[],defaultBlockWindowS} / ablation[] / parameterSensitivity{} / conclusions[] / dataStatus`。

> kpi.dataStatus 字段：`EMPTY`=该批次无 PROPOSED 算法结果（勿显示伪造 0）。全部数字来自 MySQL，前端不硬编码论文数字。
