## 8. 已知差异 / 受限项（如实说明）

1. **容差统一 10m（用户 2026-09-09 定稿）**：本系统本文移动段 DP 容差与基线统一为 10m，与 claude_15
   论文现稿"本文 15m/基线 10m"不一致 → 按本系统重跑的第 6 章数字低于现稿，论文表 6-4/6-17 等需另行回填；
   复现论文口径可把 `trajectory.experiment.dp-move-tolerance-m` 改为 15。
2. **数据源为 7709 在线库（source_data_full）**：与论文第 6 章 152 运单实验集非同一批 → 结果数字≠论文表
   （用户已确认"仅 7709"）。
3. **原始轨迹点不落 MySQL**：规格书 §2 提"MySQL 存原始 GPS 点"，§9 又要求结果表不含原始点数组；本实现取
   §9 边界，原始轨迹以本地 JSON 文件为准按需现读。如需原始点入库可在 `VisualWaybillServiceImpl` 上扩展
   `trajectory_raw_point` 快照（当前默认关闭）。
4. **消融"收紧移动段 DP 容差"**：主线已统一 10m，与论文原"A- 收紧至 10m"重合，故 A-TIGHT 取更紧的
   `ablationTightToleranceM=8m` 演示权衡（配置可改）；语义与论文 A- 不再一一对应，请按新口径重算论文消融表。
5. **车牌字段**：7709 源 JSON 无车牌；导入时从本机老业务库 `waybill` 表按 id 回填，无记录运单车牌为空。
6. **全量 7709 长跑未在本机构跑**：受时长约束只跑了 20/15 运单子集验证；全量用 `waybill-limit=-1` 由用户自行运行
   （批内支持断点/失败隔离）。
7. **高德地图渲染需联网与浏览器**：SDK 经 build 加载逻辑正确，但真实底图/Key 有效性需浏览器打开确认；
   Key 已放在 `.env.development`，如失效替换即可。
